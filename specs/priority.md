# 우선순위 기능 명세

## 목적

사용자가 각 할 일의 중요도를 한눈에 구분하고, 현재 더 중요한 일에 집중할 수 있도록 한다.

## 사용자 시나리오

1. 사용자는 새 할 일을 추가할 때 우선순위를 선택한다.
2. 사용자는 목록에서 각 할 일의 우선순위를 확인한다.
3. 사용자는 할 일을 삭제하거나 다시 만들지 않고 우선순위를 변경한다.
4. 페이지를 새로고침해도 선택한 우선순위가 유지된다.

## 기능 요구사항

### 우선순위 단계

- 우선순위는 `높음`, `보통`, `낮음`의 세 단계로 제공한다.
- 새 할 일의 기본 우선순위는 `보통`이다.
- 저장 값은 각각 `high`, `medium`, `low`를 사용한다.

### 할 일 추가

- 할 일 입력 영역에 우선순위 선택 UI를 제공한다.
- 사용자가 할 일을 추가하면 입력한 제목과 선택한 우선순위를 함께 저장한다.
- 할 일 추가 후 제목 입력값은 비우고 우선순위는 기본값인 `보통`으로 되돌린다.
- 공백뿐인 제목은 기존과 동일하게 추가하지 않는다.

### 목록 표시 및 변경

- 각 할 일 항목에 현재 우선순위를 텍스트로 표시한다.
- 색상을 사용할 수 있지만, 색상만으로 우선순위를 구분하지 않는다.
- 사용자는 목록에서 각 할 일의 우선순위를 `높음`, `보통`, `낮음` 중 하나로 변경할 수 있다.
- 우선순위를 변경해도 제목, 완료 상태, 목록 순서는 바뀌지 않는다.
- 완료된 할 일에도 우선순위는 표시하며 변경할 수 있다.

### 저장 및 기존 데이터 호환

- 우선순위는 기존 Todo 객체의 `priority` 필드에 저장한다.

```js
{
  id: "todo-id",
  title: "운동하기",
  completed: false,
  priority: "high"
}
```

- 기존 `class-todo-items` localStorage 키를 그대로 사용한다.
- 저장된 기존 Todo에 `priority`가 없거나 유효하지 않은 값이면 `medium`으로 취급한다.
- 우선순위 변경과 이후의 추가, 완료 전환, 삭제 동작은 현재 목록 전체를 localStorage에 저장한다.
- 페이지를 새로고침한 뒤에도 각 할 일의 우선순위가 유지되어야 한다.

### 접근성 및 반응형

- 우선순위 선택 UI에는 어떤 할 일의 우선순위인지 알 수 있는 접근 가능한 이름을 제공한다.
- 키보드만으로 새 할 일의 우선순위를 선택하고 기존 할 일의 우선순위를 변경할 수 있어야 한다.
- 작은 화면에서도 제목, 우선순위, 완료 체크박스, 삭제 버튼을 식별하고 조작할 수 있어야 한다.

## 기존 기능 유지

- 할 일 추가
- 완료/미완료 전환
- 할 일 삭제
- localStorage 저장
- 남은 할 일 개수 표시
- 새 할 일을 목록 맨 앞에 표시하는 현재 동작

## 범위 제외

- 우선순위에 따른 자동 정렬
- 우선순위별 필터링 또는 검색
- 사용자 정의 우선순위 단계
- 드래그 앤 드롭을 통한 순서 변경
- 마감일 또는 알림 기능

## 완료 조건

- [ ] 새 할 일을 추가할 때 `높음`, `보통`, `낮음` 중 하나를 선택할 수 있다.
- [ ] 우선순위를 선택하지 않으면 새 할 일은 `보통`으로 추가된다.
- [ ] 목록에서 모든 할 일의 현재 우선순위를 텍스트로 확인할 수 있다.
- [ ] 기존 할 일의 우선순위를 목록에서 변경할 수 있다.
- [ ] 우선순위를 변경해도 목록 순서와 다른 Todo 데이터가 유지된다.
- [ ] 우선순위가 없는 기존 저장 데이터는 오류 없이 `보통`으로 표시된다.
- [ ] 새로고침 후에도 추가하거나 변경한 우선순위가 유지된다.
- [ ] 완료 전환, 삭제, 남은 개수 표시가 기존과 동일하게 작동한다.
- [ ] 데스크톱과 작은 화면에서 우선순위 UI를 사용할 수 있다.
- [ ] 브라우저 콘솔에 관련 오류가 발생하지 않는다.
