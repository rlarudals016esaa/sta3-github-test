# 시작시간 기능 명세

## 목적

사용자가 각 할 일을 언제 시작할지 기록하고 목록에서 바로 확인할 수 있도록 한다.

## 사용자 시나리오

1. 사용자는 새 할 일을 추가할 때 시작시간을 선택적으로 지정한다.
2. 사용자는 목록에서 각 할 일의 시작시간을 확인한다.
3. 사용자는 할 일을 삭제하거나 다시 만들지 않고 시작시간을 변경하거나 지운다.
4. 페이지를 새로고침해도 지정한 시작시간이 유지된다.

## 기능 요구사항

### 시작시간 값

- 시작시간은 시와 분을 입력하는 브라우저 기본 시간 입력 UI로 제공한다.
- 시작시간은 선택 사항이며, 지정하지 않은 할 일도 추가할 수 있다.
- 저장 값은 24시간 형식의 `HH:mm` 문자열을 사용한다.
- 시작시간이 없는 경우 빈 문자열 `""`을 사용한다.

### 할 일 추가

- 할 일 입력 영역에 시작시간 입력 UI를 제공한다.
- 사용자가 할 일을 추가하면 입력한 제목, 우선순위와 시작시간을 함께 저장한다.
- 할 일 추가 후 제목과 시작시간 입력값을 비우고 우선순위는 기존 기본값인 `보통`으로 되돌린다.
- 공백뿐인 제목은 기존과 동일하게 추가하지 않는다.

### 목록 표시 및 변경

- 각 할 일 항목에 시작시간 입력 UI를 표시한다.
- 시작시간이 지정된 경우 목록에서 `HH:mm` 값을 확인할 수 있다.
- 사용자는 목록에서 각 할 일의 시작시간을 변경하거나 지울 수 있다.
- 시작시간을 변경해도 제목, 완료 상태, 우선순위, 목록 순서는 바뀌지 않는다.
- 완료된 할 일에도 시작시간을 표시하며 변경할 수 있다.

### 저장 및 기존 데이터 호환

- 시작시간은 기존 Todo 객체의 `startTime` 필드에 저장한다.

```js
{
  id: "todo-id",
  title: "운동하기",
  completed: false,
  priority: "high",
  startTime: "07:30"
}
```

- 기존 `class-todo-items` localStorage 키를 그대로 사용한다.
- 저장된 기존 Todo에 `startTime`이 없거나 유효한 `HH:mm` 값이 아니면 빈 문자열로 취급한다.
- 시작시간 변경과 이후의 추가, 우선순위 변경, 완료 전환, 삭제 동작은 현재 목록 전체를 localStorage에 저장한다.
- 페이지를 새로고침한 뒤에도 각 할 일의 시작시간이 유지되어야 한다.

### 접근성 및 반응형

- 시작시간 입력 UI에는 어떤 할 일의 시작시간인지 알 수 있는 접근 가능한 이름을 제공한다.
- 키보드만으로 새 할 일과 기존 할 일의 시작시간을 입력하거나 변경할 수 있어야 한다.
- 작은 화면에서도 제목, 시작시간, 우선순위, 완료 체크박스, 삭제 버튼을 식별하고 조작할 수 있어야 한다.

## 기존 기능 유지

- 할 일 추가
- 완료/미완료 전환
- 할 일 삭제
- localStorage 저장
- 남은 할 일 개수 표시
- 우선순위 선택 및 변경
- 새 할 일을 목록 맨 앞에 표시하는 현재 동작

## 범위 제외

- 시작시간에 따른 자동 정렬
- 시작시간 기반 필터링
- 알림 또는 리마인더
- 종료시간 또는 소요시간
- 날짜, 마감일 또는 반복 일정
- 시간대 변환

## 완료 조건

- [ ] 새 할 일을 추가할 때 시작시간을 선택적으로 지정할 수 있다.
- [ ] 시작시간 없이도 새 할 일을 추가할 수 있다.
- [ ] 목록에서 지정된 시작시간을 확인할 수 있다.
- [ ] 기존 할 일의 시작시간을 목록에서 변경하거나 지울 수 있다.
- [ ] 시작시간을 변경해도 목록 순서와 다른 Todo 데이터가 유지된다.
- [ ] 시작시간이 없는 기존 저장 데이터는 오류 없이 빈 값으로 표시된다.
- [ ] 새로고침 후에도 추가하거나 변경한 시작시간이 유지된다.
- [ ] 우선순위, 완료 전환, 삭제, 남은 개수 표시가 기존과 동일하게 작동한다.
- [ ] 데스크톱과 작은 화면에서 시작시간 UI를 사용할 수 있다.
- [ ] 브라우저 콘솔에 관련 오류가 발생하지 않는다.
